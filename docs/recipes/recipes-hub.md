## The 5 search intents worth covering first

The first-wave traffic plan should cover five kinds of intent, not just one:

1. **Recipes hub intent** — “Where should I start?”
2. **Integration intent** — “How do I use OpenClaw in Feishu or Telegram?”
3. **Troubleshooting intent** — “Why is cron not running?”
4. **Role / buyer intent** — “What does this do for a founder or operator?”
5. **Comparison intent** — “Which workflow deserves priority first?”

If you only build one of those buckets, traffic stays narrow.
If you cover all five, OpenClaw can meet users earlier and at more points in the adoption path.

## A simple priority rule

Use this order:

1. **Start with distribution** if OpenClaw is not yet inside the chat surface people really use
2. **Start with reliability** if cron or scheduled delivery already feels broken
3. **Start with signal compression** if the biggest pain is operational noise from deploys or PRs
4. **Start with role-based narrative** when the buyer needs a product story, not just setup steps

The main idea is simple:

**distribution and reliability usually deserve priority before more ambitious workflow storytelling.**
